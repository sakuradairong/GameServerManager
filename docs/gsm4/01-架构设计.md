# GSM4 架构设计

## 1. Monorepo 结构

```text
gsm4/                          # orphan 分支仓库根
  apps/
    web/                       # React + Vite 前端
    server/                    # Fastify 服务端
  packages/
    shared/                    # Zod schema、DTO、事件名、平台枚举
    migrator/                  # GSM3 → GSM4 数据迁移 CLI
  data/                        # 运行时数据（开发期示例/占位，不提交密钥）
    manifest.json              # schemaVersion 等
  docs/                        # 可同步 docs/gsm4 方案
  AGENTS.md
  package.json                 # workspaces
  README.md
```

实现阶段允许将方案文档从 `main:docs/gsm4` 拷贝/同步到 orphan 根下 `docs/`。

## 2. 逻辑架构

```text
┌─────────────────────────────────────────────┐
│ apps/web                                    │
│  features/*  →  ApiClient  →  RealtimeClient│
└─────────────────┬─────────────┬─────────────┘
                  │ HTTP        │ Socket.IO
┌─────────────────▼─────────────▼─────────────┐
│ apps/server                                 │
│  routes (thin)                              │
│    → application services                   │
│      → domain modules                       │
│        → adapters (pty / steamcmd / fs / http)│
└─────────────────┬───────────────────────────┘
                  │
         ┌────────▼────────┐
         │ data/ + 本机资源 │
         └─────────────────┘
```

### 依赖方向（强制）

- `routes` → `application` → `domain` → `adapters`
- `packages/shared` 可被 web/server/migrator 依赖
- **禁止** `adapters` 依赖 `routes`；**禁止** web 直接拼业务 URL 绕过 ApiClient

## 3. 服务端域模块

| 域 | 职责 | GSM3 对应（对照用） |
|----|------|---------------------|
| `auth` | 注册/登录/验证码/锁定/JWT | `/api/auth` |
| `security` | token 策略、external API key | `/api/security`、`/api/external` |
| `config` | 唯一配置读写（替代散落 fs） | `ConfigManager`、`/api/config`、`/api/settings` |
| `system` | 主机信息、磁盘、端口、进程、告警 | `/api/system`、Home |
| `terminal` | PTY 会话生命周期、重连、默认用户 | `TerminalManager`、`/api/terminal` |
| `instance` | 实例 CRUD、启停锁、市场元数据关联 | `InstanceManager`、`/api/instances` |
| `catalog` | Steam/MC/online 等清单读写与同步 | `installgame.json`、市场/online 列表 |
| `deploy` | **部署内核 + Executors** | game-deployment / minecraft / more-games / online / file-deploy |
| `files` | 浏览、上传、编辑、压缩解压、收藏 | `/api/files` |
| `backup` | 实例备份恢复 | `/api/backup` |
| `scheduler` | 定时任务 | `/api/scheduled-tasks` |
| `environment` | Java / VC++ / DirectX / 系统包 | `/api/environment` |
| `plugin` | 插件扫描、启停、沙箱 WebUI、受控 iframe 消息接口 | `/api/v1/plugins`、`/plugin-ui`；EasyTier 后续迁移 |
| `gameconfig` | 可视化配置 schema 与读写 | `/api/gameconfig` |
| `rcon` | 按实例 RCON | `/api/rcon` |
| `sponsor` / `wallpaper` / `weather` / `network` / `developer` | 增值与辅助 | 对应旧路由 |

遗留 **`GameManager` + `/api/games` 不再移植**；能力并入 `instance` + `deploy`。

## 4. 部署内核（核心设计）

### 4.1 统一流水线

```text
DeployRequest
  → Validator（认证用户、平台能力、路径策略、参数 Zod）
  → DeploySession.create（id、cancelToken、超时、归属实例）
  → Executor.run（按 type 分发）
  → ProgressBus.emit（统一事件）
  → onSuccess: InstanceCommit
  → onFailure: Rollback（删除本次新建实例 / 释放锁）
```

### 4.2 Executor 清单（首版规划）

| type | 说明 | 进度通道 |
|------|------|----------|
| `steamcmd` | Steam 专用服安装/更新 | `deploy:*` + 可选 `terminalSessionId` |
| `minecraft` | Java 核心 jar | `deploy:*` |
| `mrpack` | Modrinth 整合包 | `deploy:*` |
| `archive` | 本地/URL 压缩包（原 file-deploy） | `deploy:*` |
| `online` | 赞助/在线目录包（**暂缓**，不接赞助） | `deploy:*` |
| `bedrock` / `tmodloader` / `factorio` | 原 more-games | `deploy:*` |

### 4.3 Session 语义

| 字段/行为 | 约定 |
|-----------|------|
| `sessionId` | 服务端生成，前后端唯一句柄 |
| `cancel` | 合作式取消；下载流/子进程可中断 |
| `进程重启` | 内存 Session 丢失 → 客户端视为 failed/unknown，允许用户重试；不假装续传（首版） |
| `实例锁` | 与 Instance 操作锁共用规则，防止部署中并发启停 |

### 4.4 路径策略

1. **默认**：`path.join(defaultInstallPath, gameKeyOrName)`，拒绝逃逸出根。  
2. **高级**：用户显式开启「自定义路径」后允许绝对路径，仍做规范化与危险路径检查。  
3. 开发/打包双根读取只出现在 `catalog` / `config` 的 path resolver，不进各 Executor 复制粘贴。

### 4.5 解压与下载

- `adapters/archive`：zip / 7z / tar.* 统一入口；tar 必须走安全过滤。  
- `adapters/download`：http(s)、超时、取消、进度；后续可加 SSRF 防护（内网地址拒绝）。  
- 禁止业务域直接 `child_process` 拼 shell 管道作为唯一解压实现。

## 5. 前端结构

```text
apps/web/src/
  app/                 # 路由壳、布局、鉴权门闸
  features/
    home/
    terminal/
    instances/         # 子：market、gameconfig、rcon、backup
    deploy/            # 子：steam、minecraft、mrpack、archive、online、more
    files/
    environment/
    plugins/
    settings/
    about/
    developer/
  shared/
    ui/                # 弹窗（淡入淡出）、消息、表单控件
    api/               # ApiClient
    realtime/          # Socket 封装与 hooks
    lib/
```

### 前端硬约束

- 部署相关 UI 按子 feature 拆分；**禁止**单文件堆积所有 tab。  
- 所有 `/api` 走 ApiClient；设置页/引导页不得私自 `fetch`。  
- 通知走面板消息组件；交互确认走面板弹窗，不用浏览器 `alert/confirm`。

## 6. API 与实时契约

### HTTP

- 前缀：`/api/v1/<domain>/...`
- 一律认证（external 专用 key 中间件除外）
- 错误形状统一：`{ success, error, message, code?, details? }`
- 请求/响应 DTO 定义在 `packages/shared`，server 用同一 Zod 校验

### Realtime（初稿）

| 事件 | 方向 | Payload 要点 |
|------|------|----------------|
| `deploy:progress` | s→c | `sessionId, percent?, stage?, message?` |
| `deploy:log` | s→c | `sessionId, line, level` |
| `deploy:complete` | s→c | `sessionId, instanceId?, paths?` |
| `deploy:error` | s→c | `sessionId, error` |
| `deploy:cancel` | c→s | `sessionId` |
| 终端事件 | 双向 | 保留 create/input/resize/close/reconnect 语义，名称在 shared 中冻结 |

Steam 安装若需完整交互式输出：`deploy:complete` 前可带 `terminalSessionId`，UI 可跳转终端；但进度仍发 `deploy:*`，避免「只有终端、没有会话状态」。

## 7. 平台能力表

```ts
// packages/shared 示意
type Platform = 'windows' | 'linux' | 'linux_arm'

interface ExecutorCapability {
  type: DeployType
  platforms: Platform[]
  requiresSponsor?: boolean
}
```

UI 与 Validator 共用此表；ARM 隐藏 SteamCMD 不再散落魔法条件。

## 8. 安全底线（架构级）

1. 所有用户 API 认证  
2. 路径规范化 + 沙箱默认  
3. 归档解压防路径穿越  
4. Steam 凭证不落日志；runscript 权限收紧  
5. External API key 独立作用域  
6. 远程 URL 下载限制协议与目标（逐步加强）

## 9. 测试与质量（务实）

- GSM3 约定「无测试代码」不延伸为 GSM4 禁止测试。  
- GSM4：**优先**对 `packages/shared` 校验、路径沙箱、migrator 纯函数做轻量单测；不强制重型 E2E 首版齐套。  
- 每个里程碑必跑 `tsc --noEmit`（或等价）与约定的 lint。
