# GSM4 安全与发布门禁

本页记录 M0–M3 全量审查后的长期约束。发现的问题应直接修复；外部服务不可用时只记录真实状态，不加入伪造、降级或绕过流程。

## 已落实的安全边界

- **认证**：JWT 密钥持久化到 `data/`，首用户注册串行化，登录失败按 IP+用户名限流；HTTP API 和 Socket.IO 均验证 token，跨域来源采用显式允许列表。
- **持久化**：`config.json`、`users.json`、`instances.json` 和上传元数据使用原子写入；损坏文件拒绝静默覆盖。
- **路径**：默认安装目录、文件管理、上传、Minecraft JAR 和自定义安装目录统一执行目录边界与符号链接逃逸检查。
- **归档**：ZIP/TAR 均拒绝路径穿越、符号链接和超限解压；TAR 解压必须使用 `tarSecurityFilter.ts`。
- **上传**：部署文件流式落盘，单文件上限 512MB、临时目录总配额 2GB、24 小时过期清理，重启后通过受校验元数据恢复。
- **出站下载**：逐跳校验协议、重定向和 DNS 解析；Steam 目录仅接受 HTTPS，并限制为 5MB 后执行 Zod 结构校验。
- **凭证**：SteamCMD runscript 权限为 `0600`，成功、失败、取消均清理；日志会脱敏密码，前端提交后立即清空凭证状态。
- **生命周期**：终端以真实 PTY exit 作为会话结束事实；实例重启全程持锁，部署目录并发保留，终态会话按容量和时间清理。
- **前端**：token 固定使用 `gsm3_token`；401/Socket 未授权会统一注销；删除使用面板确认弹窗，弹窗包含淡入淡出；未实现功能不显示占位入口。
- **容器**：构建使用 `npm ci`，运行镜像裁剪到产物与生产依赖，以非 root 用户启动并提供健康检查；`.dockerignore` 排除本地数据和秘密文件。

## 每次交付必须通过

```bash
npx tsc -p packages/shared/tsconfig.json --noEmit
npx tsc -p apps/server/tsconfig.json --noEmit
npx tsc -p apps/web/tsconfig.json --noEmit
npm run build
npm audit --omit=dev
npm audit
git diff --check
```

同时执行：

1. 认证注册并发、token 重启有效性与 CORS/Socket Origin 回归。
2. 路径穿越、符号链接、恶意 ZIP、上传恢复/过期清理回归。
3. Steam 凭证清理、终端退出、实例重启锁和部署目录并发回归。
4. 浏览器检查登录、导航、实例、终端、部署、文件、设置的控制台与网络错误。
5. Docker 镜像构建与健康检查；若构建基础镜像或系统包源不可达，记录为外部环境阻塞，不以未验证镜像冒充通过。

项目当前不保留测试代码；临时回归脚本验证完成后删除，符合仓库约定。
