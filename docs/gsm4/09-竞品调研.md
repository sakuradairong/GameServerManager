# GSM4 竞品调研

> 调研日期：2026-08-11  
> 范围：开源及源码可见的游戏服务器管理工具；AMP 等半开源仅作对标参考  
> 目的：明确 GSM4 产品定位、差异化与里程碑优先级，**不**改变「不强制 Docker / 统一 DeploySession」的核心决策（见 [00-决策与原则](./00-决策与原则.md)）

---

## 1. 市场格局（四类）

| 类型 | 代表 | 核心卖点 | 典型用户 |
|------|------|----------|----------|
| A. Docker 托管级面板 | Pterodactyl、Pelican、Calagopus | 每服容器隔离、eggs 模板、多节点、细粒度权限 | 社区服、小型托管商 |
| B. 进程/Daemon 面板 | **MCSManager**、PufferPanel | 轻安装、Steam/MC、可选 Docker、多用户 | 中文社区、自建多机 |
| C. 垂直品类面板 | Crafty Controller | Minecraft 深度（玩家/备份/Java） | 只开 MC 的管理员 |
| D. CLI / 桌面工具 | LinuxGSM、WindowsGSM | 零/低面板开销、脚本装服 | 会 SSH 的运维、Windows 本机 |

**GSM4 归类**：类型 **B**（本机进程 + Web 面板 + SteamCMD/专用部署管线），能力目标对标 **MCSManager**，差异化在 **统一 DeploySession** 与 **Steam 分支/凭据更新**；**不**与类型 A 比 Docker 隔离与 eggs 数量。

---

## 2. 逐产品深潜

### 2.1 Pterodactyl / Pelican Panel

| 项 | 说明 |
|----|------|
| 许可 | Pterodactyl MIT；Pelican AGPL-3.0 |
| 架构 | Panel（PHP/Laravel + 前端）+ Wings（Go）；每实例 Docker |
| 游戏覆盖 | 社区 eggs 200+：MC、SteamCMD、语音、数据库、通用软件 |
| 运维能力 | 控制台（xterm）、文件 + Monaco、SFTP、定时任务（cron）、备份（本地/S3）、子用户权限、每服数据库供给、网络分配、资源限额（cgroup） |
| 多节点 | 原生：一 Panel 多 Wings |
| 安装成本 | 高：Panel + MariaDB + Redis + Wings；常需域名/HTTPS |
| 2026 态势 | Pterodactyl 节奏放缓；**Pelican** 为活跃 fork，eggs 兼容，API 兼容托管计费；Blueprint 扩展不兼容 Pelican |

**对 GSM4 的启示**

- 对方护城河是 **隔离 + 模板生态 + 多租户**，不是「装 Steam 服」本身。  
- 备份/定时/子权限是托管级「标配体验」，GSM4 缺位会被归为半成品。  
- **不要**复制 egg/Docker 运行时；可借鉴 eggs 的「元数据字段」（端口、环境变量、安装脚本）做 catalog 模板。

### 2.2 MCSManager（最近竞品）

| 项 | 说明 |
|----|------|
| 许可 | 开源（MIT 系社区面板） |
| 架构 | Web（用户/权限/API）+ Daemon（进程/Docker/文件/终端）；Node/TS |
| 部署 | 一键脚本 / Compose；Windows 解压即用；无强制外部 DB |
| 游戏 | MC 市场一键装；Steam 依赖 SteamCMD「更新命令」模板；Docker Hub 任意镜像 |
| 运维 | Web 终端、文件管理、计划任务与备份、资源监控、RCON（应对无 stdin 的 Steam 服） |
| 权限 | 多用户；角色 + 实例授权（超管/子管/普通/只读一类模型） |
| 多节点 | Daemon Token 注册；跨机纳管 |
| 商业 | 明确支持 IDC/售卖实例场景 |
| Steam 细节 | 用户手写 `steamcmd +app_update <APPID>` 到「更新命令」；启动命令自配；推荐 Linux+Docker 提高兼容性 |

**与 GSM4 对比（关键）**

| 点 | MCSManager | GSM4 |
|----|------------|------|
| Steam 安装 | 通用更新命令字符串 | `steamcmd` 执行器 + catalog + **分支查询/密码/凭据更新** |
| MC | 市场/镜像 | jar URL、**mrpack**、Bedrock、tModLoader 等专用执行器 |
| 进度契约 | 分散（更新/终端） | 统一 `deploy:*` |
| 多节点 | 有 | 无（非 M4 范围） |
| 备份/定时/RCON | 有 | M4/M5 待做 |
| 多用户 ACL | 成熟 | 仅首管理员 + 限流 |

**结论**：功能完备度上 MCSM 仍领先；GSM4 应用在 **部署内核质量** 上建立差异，用 M4/M5 补齐「面板标配」。

### 2.3 Crafty Controller

| 项 | 说明 |
|----|------|
| 许可 | GPL-3.0 |
| 栈 | Python/Tornado；单进程/单容器；SQLite |
| 覆盖 | Minecraft Java/Bedrock、Hytale；SteamCMD 多游戏「规划中」 |
| 深度能力 | 玩家管理（白名单/封禁）、备份管理器（保留数、关服备份、前后置命令）、定时任务、按服 Java 路径、官方移动端、Passkey/2FA、RBAC |
| 缺口 | 非 MC 弱；无多节点；无 Docker 硬隔离 |

**对 GSM4**：M4 备份应参考其「关服备份 / 保留策略 / 前后置命令」；M4 Java 多版本对齐「每实例 Java 路径」；不必追玩家管理到同等深度（可后置）。

### 2.4 PufferPanel

| 项 | 说明 |
|----|------|
| 许可 | Apache-2.0 |
| 栈 | Go 单二进制；SQLite/MariaDB |
| 能力 | JSON 模板、Docker/Standard 环境、控制台/文件、基础权限、定时、多节点（弱于 Ptero） |
| 定位 | 1～数台服、拒绝 Ptero 复杂度 |

**对 GSM4**：同属轻量阵营；GSM4 应用 Steam/MC **专用管道**拉开差距，而非通用模板数量。

### 2.5 LinuxGSM / WindowsGSM

| | LinuxGSM | WindowsGSM |
|--|----------|------------|
| 形态 | Bash CLI | Windows GUI |
| 游戏 | 100～120+ | 插件扩展多游戏 |
| 能力 | install/update/monitor/backup/alert/console；深度 SteamCMD | 一键装、计划重启、自动更新、Discord 告警、Mod、远程 Discord |
| 缺口 | 无 Web、无多用户 | 偏 Windows 本机 |

**对 GSM4**：catalog / 启动参数 / 依赖检测可 **引用 LinuxGSM 脚本表** 作为数据源，不引入其 CLI 运行时。

### 2.6 AMP（CubeCoders，非开源对照）

- 300+ 应用、原生进程、多节点、自动更新、商业 UI  
- 个人授权约 $10（源码可见但专有）  
- **意义**：开源面板若只比「游戏数量」，永远输给 AMP/eggs；GSM4 应比 **体验闭环与专用部署质量**。

### 2.7 Calagopus（跟踪项）

- Rust + React 从零重写，宣称 egg 兼容、扩展 API、高性能  
- 生态未稳；**仅跟踪**，不作为短期对标实现。

## 4. GSM4 定位声明（调研后确认）

1. **产品轴**：单机/少量机器上的「可开箱装服的管理面板」，优先 Steam + MC 生态。  
2. **架构轴**：保持进程模型 + 可选容器（未来可接），**不以 Docker 为默认前置**。  
3. **差异轴**：`DeploySession` 统一进度/取消；Steam **分支发现与凭据更新**；专用执行器（mrpack / Factorio / Bedrock / tModLoader）。  
4. **不对齐**：eggs 数量、强制 cgroup 隔离、WHMCS 售卖（可后置 API）、完整 Docker 多租户。  
5. **必须对齐（体验底线）**：备份、定时、角色权限、RCON、更完整的文件（压缩）、Java/环境——对应里程碑 **M4 → M5**。

## 5. 对里程碑的具体建议

与 [03-里程碑](./03-里程碑.md)、[05-下一步行动](./05-下一步行动.md) 对齐：

### M4（当前主线）— 对齐「面板标配」

优先顺序建议：

1. **实例备份与恢复**（参考 Crafty：保留数、可选关服、路径选择）  
2. **定时任务**（电源/备份/命令；参考 Pelican Schedule 的「任务链」思路，实现可裁剪）  
3. **文件压缩解压 + 收藏**（对齐 MCSM 文件体验）  
4. **Java 多版本 / 环境**（对齐 Crafty 每服 Java 路径；Win 运行库按需）

### M5 — 对齐 MCSM 运营能力（裁剪）

1. **RCON**（Steam 无 stdin 场景，MCSM 已验证需求）  
2. **admin/user + 实例授权**（先二级角色，再细粒度）  
3. **实例市场 / catalog 增强**（可吸收 LinuxGSM 游戏表字段）  
4. 插件生态扩展（EasyTier 等）；External API Key  

### 明确不做或长期跟踪

| 项 | 处理 |
|----|------|
| 强制 Docker + eggs 运行时 | 不做（路线差异） |
| 完整多节点 Daemon 联邦 | 长期；M6 后再评估 |
| AMP 级 300+ 一键库 | 不做堆数量；做质量模板 |
| Crafty 级玩家运营全家桶 | 后置；非 M4 |
