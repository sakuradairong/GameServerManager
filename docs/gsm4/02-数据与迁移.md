# GSM4 数据与迁移

## 1. 运行时数据根

与 GSM3 一样，以进程工作目录下的 `data/` 为 canonical：

| 环境 | 典型路径 |
|------|----------|
| 打包 / Docker | `process.cwd()/data` |
| 开发（可选） | 仓库内 `data/` 或 `apps/server/data/`（由 Config 解析器统一） |

所有需要持久化的面板状态进入 `data/`，禁止写到源码树。

## 2. `data/manifest.json`

```json
{
  "schemaVersion": 4,
  "product": "gsm4",
  "createdAt": "ISO-8601",
  "migratedFrom": null
}
```

- `schemaVersion`：GSM4 内演进用；migrator 读写时校验  
- `migratedFrom`：若来自 GSM3，记录 `{ product: "gsm3", sourcePath, migratedAt }`

## 3. GSM4 数据布局（初稿）

| 路径 | 内容 | 迁移优先级 |
|------|------|------------|
| `manifest.json` | 版本元数据 | 生成 |
| `config.json` | 服务、JWT、SteamCMD、默认安装路径、终端用户、安全策略、赞助等 | **P0** |
| `users.json` | 用户与角色（bcrypt） | **P0** |
| `instances.json` | 实例定义 | **P0** |
| `games/installgame.json` | Steam 部署目录 | **P0** |
| `gameconfig/*.yml` | 可视化配置 schema | **P0** |
| `rcon/<instanceId>.json` | RCON | **P0** |
| `backupdata/` | 备份实体 | **P0** |
| `scheduled-tasks.json` | 定时任务 | **P1** |
| `favorites.json` | 文件收藏 | **P1** |
| `plugins/` | 插件包与状态 | **P1** |
| `easytier/`、`tunnels/` | EasyTier / 穿透 | **P1** |
| `environment/` | Java 等运行时 | **P1**（校验路径，可重装） |
| `lib/` | PTY / Zip-Tools 二进制 | **P2**（可重新下载） |
| `wallpapers/` | 壁纸 | **P2** |
| `login_attempts.json` / `captchas.json` | 安全临时 | 不迁 |
| `terminal-sessions.json` | 活跃会话 | 不迁（可重建） |
| `*/temp/` | 部署临时 | 不迁 |
| `logs/` | 日志 | 不迁 |

## 4. 实例模型（迁移焦点）

GSM3 实例字段需映射到 GSM4，至少保留：

- 身份：`id`、`name`、`description?`
- 运行：`workingDirectory`、`startCommand`、`stopCommand`、`autoStart`
- Steam：`steam.appId`、`steam.gameKey`、`steam.branch`（及 beta 相关若有）
- 运行时：`instanceType`、`javaVersion?`、`programPath?`
- 终端：`terminalSessionId?`、`terminalUser?`、`enableStreamForward?`

迁移时：

1. **保留 `id`**，避免 RCON/备份/外部 API 引用断裂  
2. 校验 `workingDirectory` 是否存在；不存在则标记 `migrationWarnings`  
3. 启动命令字符串原样保留（不在迁移期「智能改写」）

## 5. 配置映射

| GSM3 | GSM4 | 说明 |
|------|------|------|
| `jwt.secret` | 同义字段 | **尽量保留**，避免全员掉线；若策略变更则文档说明需重登 |
| `steamcmd.*` | `steamcmd.*` | 校验可执行文件是否存在 |
| `game.defaultInstallPath` | `game.defaultInstallPath` | 核心沙箱根 |
| `terminal.defaultUser` | `terminal.defaultUser` | Linux |
| `sponsor.*` | `sponsor.*` | |
| `security.*` / `externalApi.*` | `security.*` | key 哈希可保留 |

字段名允许在 GSM4 内重命名，但 migrator 必须有显式映射表（写在 `packages/migrator` 与本文档同步更新）。

## 6. 迁移工具 `packages/migrator`

### CLI 示意

```bash
gsm4-migrate --source /path/to/gsm3/data --target /path/to/gsm4/data --dry-run
gsm4-migrate --source /path/to/gsm3/data --target /path/to/gsm4/data --apply
```

### 步骤

1. 检测源是否像 GSM3（存在 `instances.json` / `config.json` 等）  
2. Dry-run 生成报告：将复制的文件、字段映射、警告（路径缺失、未知字段）  
3. Apply：写入目标；设置 `manifest.migratedFrom`  
4. **不修改**源目录；**不移动**游戏服务端文件  

### 报告输出

- `migration-report.json` + 人类可读摘要  
- 退出码：`0` 成功；`2` 有警告但完成；`1` 失败

## 7. 客户端本地存储

| GSM3 | GSM4 |
|------|------|
| `gsm3_token` | `gsm4_token`（可读旧键一次并迁移） |
| `gsm3_user` | `gsm4_user` |
| `gsm3_developer_token` | `gsm4_developer_token` |
| 主题/壁纸/引导等 | 新前缀或版本化 key；可尝试迁移主题偏好 |

## 8. Docker / 卷契约

过渡期建议：

- GSM3 卷：继续挂旧面板  
- GSM4 卷：新 `data`；游戏目录 **同一 host path 挂载**，保证实例 `workingDirectory` 迁移后仍有效  

文档需给出 compose 示例：面板数据分离、游戏目录共享。

## 9. 不做的事

- 迁移期自动「升级」游戏服务端版本  
- 静默丢弃未知实例字段（应保留到 `extras` 或警告）  
- 在线读取旧 GSM3 进程内存态（只迁磁盘）
